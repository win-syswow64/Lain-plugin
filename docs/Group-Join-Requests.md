# 入群申请通知与审批

Lain app `apps/group_join_request.js` 内置申请通知与审批，无需再安装附件中的独立插件。使用前移除或停用旧的独立通知插件，避免同一请求通知两次。已有的 `apps/qqbot_join_request.js` 继续提供主人手动拉取列表、审批和拒绝时拉黑的命令。

## 接收申请

适配器需提供 `request.group.add` 事件和 `e.approve(同意与否)` 方法。QQBot 的 `GROUP_JOIN_REQUEST` 已转换为此事件；ICQQ、OneBot 等提供相同兼容事件的适配器也可使用。

收到申请后，自动向申请所在群发送通知，包含申请人头像、昵称、申请理由以及管理员问答。头像取自事件成员对象，不调用群成员列表或详情 API。头像上传失败时，可去掉头像重发纯文字通知。未提供头像的事件也能正常通知。

群对象优先使用事件的 `e.group`；数字群号可回退到 `Bot.pickGroup()`。群通知失败（包括 QQBot 群未开启主动推送）时，按云崽的 `masterQQ` 配置尝试私聊主人，成功发送给一位即停止。数字 QQ 号和 `机器人ID-用户ID` 格式均可配置；对应适配器仍须具有给主人的私聊发送权限。

## 引用审批

在通知消息上使用 QQ 的“回复/引用”，发送以下任一条：

```text
同意
拒绝
#同意
#拒绝
```

群内允许群主、管理员和机器人主人审批；私聊主人收到兜底通知后，也可引用通知审批。私聊仅限机器人主人。

群管理员身份使用事件已有的 `member.is_admin/is_owner` 布尔值或成员角色，不额外请求官方成员详情接口。如果 QQBot 未提供可确认的管理员角色，主人仍可引用审批，群管理员可使用通知下方的管理员按钮。

只匹配本 app 缓存的通知，不处理其他插件的引用命令。引用缓存按机器人、会话类型、群或用户及消息 ID 区分，兼容官方消息 ID 与 ICQQ 引用历史查询。开启 ICQQ 转译时使用原始 AppID/OpenID 匹配上下文。

## QQBot 管理员按钮

QQ群通知额外附带“同意”“拒绝”回调按钮，官方按钮权限设为仅群管理员可用。点击后直接审批，用户无需再发送消息。私聊兜底通知不携带群管理员按钮。

审批命令包含随机申请标识；app 同时核对当前机器人和群、按钮在本机的登记信息及管理员权限。仅有 `callback` 事件类型或在普通消息中写入申请标识不能取得权限。按钮的本地登记与申请通知均保留 1 小时。

QQBot 使用 raw 或模板 Markdown 时显示原生按钮；legacy 模式会将按钮转为文字指令提示，此时应使用主人引用审批，或使用事件中已能确认的群管理员角色审批。

审批使用原始请求事件的 `approve()`，保留官方申请 ID；即使同一成员有多次申请，也不会按成员 ID 随意选择其他申请。已审批的申请不会重复提交；并发点击时提示正在处理。适配器明确返回失败时保留申请并提示原因，可在问题解决后重试；权限错误沿用 QQBot 的统一提示。

## 有效期和限制

- 请求及通知缓存保留 1 小时，到期自动清理；重启后清空。
- 群推送、私聊发送、申请事件订阅和审批接口仍需机器人具备相应权限；本 app 不代替平台授权。
- 同一请求的重复事件在缓存有效期内去重；已处理状态保留至过期。
- 普通协议端没有回调按钮时，使用引用审批即可。
- 通知和审批功能由 app 自动加载，不需要新增 button 扩展文件。

需要手动拉取未收到通知的申请时，参见 [QQBot 群管理与入群申请](./QQBot.md)。
